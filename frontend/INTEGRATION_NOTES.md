# PropertyVault integration handoff

This document maps the **existing** prototype actions to future integration work. All current operations remain local demo actions. No Anchor repository, IDL or deployed program was available as part of this export; no account names, instruction signatures, PDAs or program IDs are asserted here.

## Current model boundaries

- `src/lib/propertyStore.js` owns canonical demo state and mutation validation. Its `window.PVStore` API is the narrowest initial adapter boundary: `properties`, `property`, `investor`, `balance`, `createListing`, `investmentCheck`, `purchase`, `setInvestor`, `subscribe` and `snapshot`.
- `src/types/property.ts` describes the current demo schema only. Decimal listing amounts and micro-USDC ledger strings are different units. BigInt calculation helpers must not be replaced by floating point when integrating transfers.
- `CreatePropertyWizard.js` retains listing form validation, amount formatting and offering/allocation calculations. `InvestmentFlow.js` retains the property-level investor pool display. `InvestorDashboard.js` retains finalized-period totals and the explicitly labeled illustrative personal projection.
- `dashboard-shell.html` and `dashboardController.js` retain the owner shell, navigation and ancillary screens/dialogs. Separate React flow roots and window APIs are intentional preservation boundaries, not invented blockchain interfaces.
- `walletSession.js` owns the real Phantom connection and exposes one external store to the navbar and investor preview. Its public key is not used to authorize or personalize the local demo ledger. Devnet is an app setting, not a claim about Phantom's selected network or RPC health.

## Open contract questions

Unsold token treatment is not finalized. The personal rental estimate in the investor detail view explicitly states its fixed-supply assumption; it must not become an entitlement calculation by accident. The investment wizard presents only the property-level estimated investor pool. Finalized rental income must come from actual collected rent and verified distribution rules, independent of estimates. Tokens confer contractual economic participation, not title ownership.

Before replacing demo actions, inspect the actual repository's program sources, tests and generated IDL. Establish listing identities, authorities, mint/vault relationships, decimals, registration requirements, period finalization and claim semantics from those verified sources. Keep the demo data clearly separated while introducing authoritative reads and confirmed transaction results incrementally.
